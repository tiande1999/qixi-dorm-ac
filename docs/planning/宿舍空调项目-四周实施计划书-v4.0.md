# 宿舍空调自动关机项目：四周实施计划书

版本：v4.0｜编制日期：2026-10-31｜周期：从正式启动日算起的 28 天  
人员：两名同学 H、S ＋ AI 技术协作  
适用对象：项目成员、指导老师，以及后续分阶段接手的 AI。

> 本次交付的是计划书。后续 AI 任务均列为“待阶段启动”，由你们到阶段时通知我执行；本次不提前编译、改固件、配置板卡或开展硬件实验。已有源码继续作为待核验的基础。本文替代旧方案的八周排期，保留已经确认的核心功能和实物验收要求。

## 1. 项目目标与四周完成标准

做出一台独立低压设备：**门口双红外判断进出方向 → EG800Z 从人工校准值累计人数 → 人数为零且关门等条件连续成立 15 分钟 → ESP8266 发射已验证的 OFF 指令 → 真实空调进入原遥控器关机后的待机状态。**

| 项目 | 四周版决定 |
|---|---|
| 场景 | 宿舍单一出入口、单人依次通行的实物原型 |
| 主控 | 已有 EG800Z，唯一人数、计时和自动关机决策者 |
| 门口检测 | 双 E18-D80NK 漫反射红外 ＋ 干接点门磁；能否覆盖以现场实测为准 |
| 红外执行 | ESP8266 学习、保存、发射目标空调 OFF；首版保存一台空调 |
| 交互 | 本地人数显示、校准按键、学习入口、独立暂停开关 |
| 自动运行 | 全天、本地、断网继续；正常自动关机不需要每次人工确认 |
| 新增预算 | 约 100 元；电源、数据线、万用表、焊接工具借用 |
| 四周必须完成 | 真实门口计数、真实 900 秒等待、真实红外发射、真实空调关机连通 |
| 后续再做 | 手机配对页面、PWA、云服务器、远程控制、多房间、多品牌大码库、节能统计、自制 PCB |

人数为零来自“校准值＋进出累计”，不能改成“15 分钟没有运动”。“真实关机”不是切断 220V。红外发射成功不是空调状态反馈；屏幕显示“已发送关机指令”，不能自行宣称“已确认空调关闭”。

四周内优先交付一台经过验证的原型。保留首次学习能力，但不把“兼容所有空调”列为验收承诺。原定计数异常停用、重启未知、15 分钟、最终输入复核等要求不因缩期删除。

## 2. 分工方法：把能数字化完成的工作尽量交给 AI

### 2.1 三种标签

| 标签 | 含义 | 完成依据 |
|---|---|---|
| **【AI主责】** | 我负责资料核对、设计、计算、源码、脚本、测试分析和文件制作；资料齐全后通常可以直接产出 | 可审阅的文件、计算依据、测试或编译日志 |
| **【人工必做】** | 需要触碰设备、改变现场或观察实物的动作，由 H/S 完成；我提供操作卡并解释结果 | 实物、测量值、原始日志、照片或视频 |
| **【协作验证】** | 我先设计/实现，你们采集实测数据，我再判断、修改，你们复测 | 数字结果与现场结果都具备 |

“AI主责”不等于已经验证实物，也不等于所有任务都很轻松。常规代码、计算、表格、接线图容易交给我；陌生空调协议分析、板卡特殊兼容问题、门口光学覆盖和间歇性干扰，需要实测迭代，不能承诺一次完成。

### 2.2 两名同学不再分别从头承担整套软硬件

| 成员 | 主要职责 | 不必独立承担的工作 |
|---|---|---|
| **H：实物与安装负责人** | 型号登记、借工具、采购执行、接线焊接、测量、支架与固定、操作遥控器 | 从零查完器件资料、独立设计电路、独立写 ESP 程序 |
| **S：工具与验证负责人** | 连接电脑、运行给定命令、烧录/上传配合、导出日志、逐次人数对账、记录版本与问题 | 从零写状态机、串口协议、计时器、测试框架和完整报告 |
| **AI：设计与软件负责人** | 分模块设计、参数计算、代码实现与修复、电脑测试、日志分析、图纸、操作卡、报告整理 | 无现场设备时不代替实物测量，不替你们确认空调实际状态 |
| **H＋S** | 上电前互查、真实计数和空调试验、最终演示 | 无需两人同时盯所有电脑端开发步骤 |

烧录、日志导出和电脑操作也优先尝试由我完成：如果届时电脑工具能访问连接的板卡及正确串口，我可在你们启动该阶段后运行可用命令；否则我提供准确命令或界面步骤，S 执行并返回输出。**插线、按物理启动键、查实物标签、焊接、拿万用表测量、在门口走动和观察空调，才是不能远程替代的动作。**

### 2.3 工时与推进假设

以每人工作日约 1～1.5 小时、每周两天各约 2～3 小时为排程假设，两人四周合计约 72～108 人时。学习包含在实验中，不额外安排完整课程。器件尽量在 D4 前到位或借到；第一周能接触目标空调和原遥控器。

AI 开发在阶段启动后与人工备料、测量并行，但不把 AI 任务当作零耗时。每个实验把“动手操作”和“等待 AI 分析”分开安排；最后一周保留修复与复测时间。若器件、空调使用时间或板卡资料迟到，按第 10 节调整，不能把未做的实测写成完成。

这样安排后，硬件中的资料、原理、电路、计算、图纸、诊断程序和分析均由 AI 主责。人不需要先学会从零画整块 PCB 才能开始，但必须会按图连接和测量。**四周首版使用开发板、现成模块和洞洞板，不把 PCB 打样和自制复杂外壳加入关键进度。**

电路细节到 A1/A2 阶段根据实物定稿。尤其不能依据“EG800Z”这个简称猜 GPIO 电压；也不能按 E18 的常见线色直接接线。光耦输入与“整机所有部分电气隔离”是不同概念；本项目与空调通过无线红外通信，不连接空调内部线路。

## 4. 模块学习路径、实现步骤与连接

### M0 基础环境、供电与引脚

- **人工最低学习**：分清电源电压与 GPIO 电平；认识 GND、TX/RX、上拉；万用表直流电压和断电通断测量；能运行/停止一个脚本并复制完整日志。
- **AI主责**：查对应板卡资料、明确所需驱动/固件、整理安装步骤、制作引脚表、写最小输入输出与串口程序。需完整固件烧录时先确认型号和现有固件，不能混用其他模组固件。
- **人工必做**：记录板卡、插 USB、必要时按物理键、测电压、核对端口。
- **路径**：型号确认 → EG 最小脚本 → ESP 最小程序 → 电压记录 → 引脚资源确认 → 分模块接线。
- **连接**：为所有模块提供已核验的供电与信号电平；EG 与 ESP 同盒，短 UART。
- **完成证据**：两块板独立运行日志、实际板卡/固件信息、引脚电压表。

学习入口是官方的板卡准备、驱动、QPYcom 和固件流程，但必须与手里的开发板相符：[EG800Z 开发板指南](https://developer.quectel.com/doc/quecpython/Dev_board_guide/zh/eg800z-duino-evb.html)。

### M1 双红外与门磁采集

- **人工最低学习**：漫反射与对射的区别；触发/释放；哪只为 A/B；如何调位置并记录；10ms 消抖不等于能消除所有干扰。
- **AI主责**：输入适配电路、采集程序、事件时间戳、消抖、有界队列与溢出异常、轨迹导出和分析工具。
- **人工必做**：接线、安装、遮挡、开门、走动、调灵敏度；用真实路径产生数据。
- **路径**：单独 A → 单独 B → 门磁 → 三路一起记录 → 门口覆盖与门板干扰实验。
- **连接**：A/B/门磁 → 电平适配 → EG 输入 → 带时间戳事件队列 → M2/M3。
- **完成证据**：原始触发/释放记录；深浅衣服、两侧和中间无稳定漏检区；空开关门 20 次不结算为进出。

### M2 方向识别、人数与校准

- **人工最低学习**：读懂一条进出轨迹；知道未知、不可信和 0 的区别；会按键校准实际人数；知道折返为什么暂停自动运行。
- **AI主责**：完整状态机、超时与异常、人数增减、校准流程、轨迹回放、电脑测试与修复。
- **人工必做**：给出实际人数，完成进出与折返试验，逐次人工对账。
- **路径**：电脑轨迹验证 → EG 单事件采集 → 真实轨迹回放 → 本地校准 → 100 次单人正常通行验收。
- **连接**：M1 事件 → M2 → `count / trusted / reason / state_version` → M3 和显示。
- **完成证据**：正常进出与累计值一致；超时、歧义、下溢、事件溢出不会继续授权自动关机。

示例：`00→10→11→01→00` 为进入；反向为离开。传感区域不重叠时，可由完整先后触发与释放判断，不能只凭“第一只被挡”加减人数。启动人数为未知，不能自动置零。

### M3 连续 15 分钟与关机决策

- **人工最低学习**：能够说清计时的开始、取消和只执行一次；看懂倒计时与暂停原因。
- **AI主责**：非阻塞计时、回绕处理、资格复核、取消、状态版本和每次空房一次执行；虚拟时钟测试和日志。
- **人工必做**：真实等待 900 秒；在临近到期时进入、开门、暂停；核对屏幕和实际动作。
- **路径**：电脑模拟时钟 → 板上显示倒计时 → 进入/开门取消 → UART 联动 → 完整真实等待。
- **连接**：M2 可信人数＋M1 门磁＋M5 暂停/ESP 状态 → EG 决策 → M5 执行请求。
- **完成证据**：不早发、取消有效、重启/失联不恢复旧许可、同一次空房不反复发射。

开始条件同时成立：人数已校准且可信、人数 0、门关稳定 2 秒、自动开启、ESP 通信正常、配置经真实空调验证。新的 A/B 触发先取消倒计时，再处理完整通行；门开、暂停、异常也取消。EG 重启人数未知；ESP 重启或失联取消并重新建立会话与计时。断网不取消本地控制。

时间实现采用 `utime.ticks_ms()` 与 `utime.ticks_diff()`；官方说明计数值会回绕，不能简单相减，也不能用阻塞休眠代替事件处理：[utime 文档](https://developer.quectel.com/doc/quecpython/API_reference/zh/stdlib/utime.html)。

### M4 首次学习与真实红外执行

- **人工最低学习**：OFF 与开关切换的区别；怎样对准接收头；怎样判断真实关机；怎样记录原状态和重复 OFF 结果。
- **AI主责**：接收/发射程序、协议或原始时序分析、完整数据保存、配置校验、学习状态流程、MOSFET 驱动设计和调试方案。
- **人工必做**：按原遥控器、改变空调运行状态、观察实物、按键确认现场结果、调整发射位置。
- **路径**：两次捕获 OFF → 对比数据 → 识别协议优先，未知协议受控回放 → 开机能关 → 已关不打开 → 其他原运行设置也能关 → 保存配置。
- **连接**：原遥控器 → 接收头 → ESP 配置；EG 许可 → ESP → MOSFET → 红外 LED → 真实空调。
- **完成证据**：型号、协议/原始数据、配置编号、测试条件和视频；首次验证后正常自动关机无需再人工批准。

空调遥控常携带完整状态，不能当成所有设备都适用的短按键码。未知协议的完整录波、载波与回放可能需要多轮实验，因此协议逆向列为协作难点，不列为 AI 轻松必达项：[IRremoteESP8266 FAQ](https://github.com/crankyoldgit/IRremoteESP8266/wiki/Frequently-Asked-Questions)。

### M5 UART、屏幕、按键与整机联调

- **人工最低学习**：TX 接 RX；电压不合适不能直连；会查看当前人数、配对和暂停状态；会导出完整日志、记录版本。
- **AI主责**：帧格式、校验、心跳、会话、准备/提交/取消、重复和过期拒绝；OLED 和按键程序；故障测试脚本与报告。
- **人工必做**：连线、按键、拔插与重启实验、观察显示和发射；连接设备供工具下载。
- **路径**：两板收发 → CRC 与会话 → 执行握手 → 显示/校准/学习 → 故障测试 → 离线闭环。
- **连接**：EG↔ESP UART；EG 输入按键/暂停；ESP 输出 OLED 与红外。
- **完成证据**：两板重启旧指令失效；重复 COMMIT 不重复发射；ACK 丢失不自动补发；显示明确区分发射结果和空调真实状态。

软件串口的最终引脚、库版本和红外发射期间的行为，由 AI 编译检查并安排板上验证；参考项目为 [EspSoftwareSerial](https://github.com/plerup/espsoftwareserial)。

## 5. 各模块怎么连接、装在哪里

### 5.1 信号关系

```text
双红外 A/B ──输入适配──┐
门磁 ─────────────────┼→ EG800Z：采集→计数→可信度→900秒→最终复核
校准按键／暂停状态 ────┘                     │               ↑
                                 UART 准备/提交      状态/结果
                                             ↓               │
原遥控器 → 红外接收头 → ESP8266：学习、保存、一次性执行、屏幕
                                             │
                                    MOSFET＋限流＋红外LED
                                             │ 无线红外
                                             ↓
                                          真实空调
```

空调没有返回状态箭头。传感器用的红外检测与遥控关机用的红外收发是两套不同电路。ESP 不根据人数自行决定关机。

### 5.2 实物连接与位置表

| 部件/接口 | 连接 | 安装位置/初始参数 | 定稿责任 |
|---|---|---|---|
| A 传感器 | 适配后到 EG 输入 A | 门锁侧固定支架靠走廊端；朝通道对面 | AI 画图，H 安装，H/S 测覆盖 |
| B 传感器 | 适配后到 EG 输入 B | 同一支架靠室内端；与 A 沿行进方向先取约 20cm | 同上 |
| A/B 整体 | 传感器供电按所购规格 | 高约 0.9～1.1m；可调间距、角度与灵敏度 | AI 根据门宽/扫掠修订 |
| 门磁 | 干接点到 EG 输入，按 GPIO 电压上拉 | 固定端在门框上部，磁铁在门板对应位置 | AI 接线图，H 测实际吸合距离 |
| 控制盒 | EG、ESP、保护电路同盒 | 门内固定墙面约 1.3～1.5m，避开门板 | AI 布置图，H 固定 |
| OLED | ESP GPIO4 SDA、GPIO5 SCL（预分配） | 控制盒正面 | AI 软件与接线，H 连接 |
| 学习接收头 | ESP GPIO13（预分配） | 控制盒正面，便于遥控器对准 | AI 核对型号针脚，H 安装 |
| 发射控制 | ESP GPIO14 → MOSFET 驱动 | 发射 LED 靠空调接收窗，初值约 5～15cm | AI 电路，H 调整位置 |
| 发射线 | 低压引线，按最终长度复测 | 沿墙固定，不悬垂、不夹门缝、不挡原遥控器 | AI 布线建议，H 安装 |
| 板间串口 | EG TX→ESP GPIO12 RX；ESP GPIO16 TX→EG RX；按需电平转换 | 同盒短连线，9600/8N1 为起点 | AI 核对，H 接线，S 实测 |
| ＋／－／确认 | EG 三路输入 | 控制盒正面 | AI 长按/消抖程序，H 接线 |
| 暂停开关 | 双刀：一组断开发射 LED 供电；另一组为 EG 提供独立干接点状态 | 控制盒易触及处 | AI 定稿，H 连接；不可把 5V 发射支路直接接 EG 输入 |

以上 ESP 均为 GPIO 编号，不是开发板 D 标号。EG 排针、UART 编号、电压和引脚复用仍待核对；未确认前不写“照着接”的最终图。先检查至少 A/B/门磁/三按键/暂停所需输入以及 UART 是否可用；若资源冲突，由 AI 优先研究复用调整，新增扩展器需同时核算预算与工期。

### 5.3 最小接口约定

| 接口 | 必须带的信息 | 由谁实现 |
|---|---|---|
| 采集→计数 | 来源、触发/释放、单调时间、事件顺序；丢失必须报告 | AI 写程序，H/S 产生并核对轨迹 |
| 计数→控制 | 人数或未知、可信标记、原因、状态版本 | AI |
| EG→ESP | 协议版本、双方启动会话、命令号、配置号、校验 | AI |
| 准备→执行 | ESP 返回最长 2 秒临时标识；EG 复核状态后提交；标识一次性消耗 | AI，实现后人工做故障验证 |
| ESP→EG | 就绪、已验证配置、发射阶段/错误、心跳 | AI |
| EG→显示 | 人数、是否可信、暂停/学习、剩余秒数、已发送/结果未知 | AI |

准备超时、旧会话、重复命令、错误校验不发射；ACK 丢失不自动补发。已经开始的红外不能撤回。手动学习试发是显式操作，不由 ESP 的人数逻辑触发。

| T03 | 覆盖与门干扰 | 深浅衣服、两侧/中间、快慢走无稳定漏检区；无人开关门 20 次不计人 | 组合设计、轨迹分析、位置修订 | 走动、开门、记录实际路径 |

| T07 | 临界取消 | 第 899 秒附近进入、开门或暂停，已处理的取消阻止尚未开始的发射 | 操作卡、事件与提交时序核对 | 按计划触发并记录实际时间 |

记录字段：测试编号、日期、操作者、硬件/固件版本、配置编号、初始真实人数、初始空调状态、操作步骤、原始事件、预期、实际、是否通过、缺陷编号、视频/日志位置。

**证据层级必须分开**：代码存在 → 电脑测试通过 → 编译成功 → 已上传/烧录 → 单板运行 → 整机实测。任何一级不自动证明下一层。测试通过只证明已覆盖场景；两路同时漏检、紧跟被当一人、某些断线呈未触发，简单开关量方案可能无法识别。

## 10. 关键节点与延期处理

| 最迟检查点 | 若未通过 | AI 下一步 | 人工下一步 / 排程取舍 |
|---|---|---|---|
| D3 板卡/工具可用 | 版本不明、固件不匹配、引脚不够、程序不运行 | 核对型号和错误，给最小复现/恢复步骤；不猜针脚 | 补丝印/电压/日志，必要时借同型号可用板；并行做现场尺寸 |
| D4 关键器件到位 | 接收、发射或传感器未到 | 明确兼容替代规格，先完成数字端设计/测试 | 优先借用或本地取件；实际验证日顺延并占用缓冲 |
| D7 真实 OFF | 只有开关切换、录波不全、目标不响应 | D8～D10 专项查捕获完整性、协议、载波、驱动与位置 | 补遥控器数据与实机观察；D10 仍不行，明确目标空调尚不支持，决定是否更换可用目标/延长时间 |
| D10 门口布设 | 远侧漏检或门板伪触发无法消除 | 对比轨迹与尺寸，提出调整支架/传感器方案及成本 | 实际调整或借替代；未通过不启用自动关机，不用缩窄测试路径掩盖盲区 |
| D14 计数 | 100 次对账失败、异常不能阻止自动 | 用失败原始轨迹定位并修复 | 复测失败项并重新完整计数；挤占外观优化时间 |
| D21 闭环 | 未完成真 900 秒或联动故障 | 定位关键阻塞，只保留必须功能 | 优先修主流程；不把 15 秒演示说成 15 分钟完成 |
| D25 仍有关键故障 | 会误判空房/旧指令会执行/OFF 不可靠 | 修复和重新测试；报告未达成项 | 保留暂停，交付阶段成果及剩余计划，不能宣布整机完成 |

第一优先级是“可验证的真实闭环”；第二是“异常停用、暂停、校准、恢复”；第三是外壳美观、界面丰富程度和附加功能。前两项不能通过删规则来换进度。
