# 给后续 AI 的接手说明

先读 [README](../README.md)、[项目状态](STATUS.md) 和当前用户的新要求。历史文档用于理解方案，不自动代表用户要求马上执行其中所有阶段。

## 已确定的事情

- 产品名：栖息。目标是宿舍人数为零且门关稳后，本地连续等待 15 分钟，再向真实空调发独立 OFF。
- 主控 EG800Z，执行器 ESP8266；双红外 + 门磁；新增预算约 100 元；两人四周，AI 分阶段承担设计、代码和分析。
- 网页是当前可操作演示，重点在 UI 与交互；暂不扩大后台接口范围。
- 网页支持 4/6 人寝、新手引导、红外教程、1～60 分钟、自定义等待期内提前确认；未确认到点自动执行。
- 网页最高优先级提醒只指页面内；系统通知是可选的模拟提醒，后台远程推送尚未接入。

## 接手时不要混淆

1. 实物与模拟器不是同一套状态。网页没有接硬件，实体固件没有自定义网页时长或提前确认接口。
2. 实物人数来自校准与进出累计，不是无动作超时；重启不能直接设零。
3. 发射成功不等于空调关闭。没有真实反馈时只能报告已发送。
4. EG 板卡型号、引脚、电压和空调协议未知；保持待测，不猜值。
5. 保留实物 900 秒规则；加速仅用于电脑模拟和逻辑测试。

## 代码与验证入口

- 网页：`web/dist/`；运行 `python -m http.server 4173 --bind 127.0.0.1 --directory web/dist`。
- 固件：`firmware/eg800z/`、`firmware/esp8266/`。
- 已有测试：`python tools/check.py`。
- 发布网页：`python tools/package_web.py`，产物仅含网页静态文件。
- 国内托管说明：[deploy/README.md](../deploy/README.md)。不要把默认域名存在等同于中国内地已验证可访问。

## 到实物阶段时怎么协作

用户到阶段时启动工作。先处理 AI 能完成的资料、设计、代码与诊断，再给人明确的接线、测量或测试步骤。需要实物证据就列具体测点和预期现象，不用“请检查所有接线”这样的泛泛建议。

身份验证、短信、实名和现场动作由用户完成。使用工具验证真正发生的结果，未部署、未编译、未实测的部分如实写明。
